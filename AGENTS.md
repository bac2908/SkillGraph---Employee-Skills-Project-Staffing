# Project working instructions

Every new feature or meaningful behavior change must have a corresponding
Vietnamese document in `docs/`, named clearly in lowercase kebab-case, for example
`docs/project-activity.md`. Update existing documentation when extending a feature.

Document purpose, implemented scope, relevant files/API, setup or migrations,
permissions, usage, verification commands/results, and known limitations. Distinguish
implemented functionality from proposals. Never put credentials or live secrets in docs.

Keep `docs/README.md` up to date as the documentation index. Do not consider a
feature complete until its documentation is saved and linked in the handoff.
